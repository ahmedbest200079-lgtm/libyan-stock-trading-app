# دليل التشغيل والتركيب — شاشة عرض أسهم سوق المال الليبي

دليل عملي خطوة بخطوة لفريق تقنية المعلومات وموظف التقارير.

---

## 1. فكرة العمل

```
 ┌─────────────────────┐      ┌───────────────────────┐      ┌──────────────────────┐
 │ قسم المؤشرات والتقارير│      │  منظومة التغذية        │      │  شاشة العرض           │
 │ يُصدر «تقرير عمليات   │ ───► │  lsm_feeder.py        │ ───► │  lsm-market-display  │
 │ التداول» Excel/PDF   │ حفظ  │  تقرأ التقرير وتطابقه   │ ملف  │  تقرأ session.json    │
 │ في مجلد التقارير       │      │  وتكتب session.json    │      │  وتتحدث كل 5 ثوانٍ     │
 └─────────────────────┘      └───────────────────────┘      └──────────────────────┘
```

- **لا يحتاج النظام إنترنت** ولا قاعدة بيانات ولا ربطًا مباشرًا بنظام التداول. الرابط الوحيد هو «مجلد التقارير».
- الموظف يحفظ التقرير في المجلد كما يفعل الآن ← خلال ثوانٍ تظهر الأرقام على الشاشة.

## 2. الأجهزة

| البند | المواصفات الدنيا | ملاحظات |
|---|---|---|
| جهاز شاشة العرض | ويندوز 10/11 (64-بت)، معالج i3 أو ما يعادله، ذاكرة 4GB، مساحة 1GB | يكفي جهاز صغير (Mini PC) خلف الشاشة. يمكن أن يكون هو نفسه جهاز التغذية |
| الشاشة | تلفاز أو شاشة عرض بمنفذ HDMI، دقة 1920×1080 أو 4K | تُضبط بالخيار `--scale` |
| الشبكة (اختياري) | اتصال بالشبكة الداخلية | فقط إذا كان مجلد التقارير على جهاز آخر |
| مزوّد طاقة احتياطي UPS | يُنصح به | لحماية الجهاز من انقطاع الكهرباء |

**التوصية:** جهاز واحد يشغّل الشاشة والتغذية معًا، ومجلد التقارير مجلد مشترك عليه يصل إليه موظف التقارير من جهازه.

## 4. الحصول على الحزمة الجاهزة لويندوز

يبني GitHub البرنامج تلقائيًا عند كل تعديل، ويشغّل الاختبارات، ويجمع كل ما يلزم في مجلد واحد.

1. ادخل إلى صفحة المستودع على GitHub ← تبويب **Actions**.
2. اختر **LSM display — Windows build** ← آخر تشغيل ناجح (علامة ✔ خضراء).
3. من أسفل الصفحة في قسم **Artifacts** نزّل `lsm-market-display-windows` (ملف zip).
4. فك الضغط في مجلد ثابت على جهاز العرض، مثلًا: `C:\LSM\display`

محتوى المجلد:

```
C:\LSM\display\
  lsm-market-display.exe        ← برنامج الشاشة
  *.dll , platforms\ …          ← مكتبات Qt (لا تُحذف)
  data\session.json             ← بيانات الجلسة (تكتبها التغذية)
  data\companies.json           ← الملف المرجعي للشركات
  tools\lsm_feeder.py           ← منظومة التغذية
  tools\requirements.txt
  start-display.bat             ← تشغيل الشاشة (ملء الشاشة + إعادة تشغيل آلية)
  start-feeder.bat              ← تشغيل التغذية (مراقبة مجلد التقارير)
  install-feeder.bat            ← تثبيت متطلبات التغذية (مرة واحدة)
  convert-report.bat            ← تحويل تقرير يدويًا بالسحب والإفلات
```

## 5. التركيب (مرة واحدة)

### أ) جهاز العرض

1. فك الحزمة في `C:\LSM\display` (البند 4).
2. شغّل `lsm-market-display.exe` مرة للتجربة — يجب أن تظهر الشاشة بأرقام آخر جلسة.
   - إن ظهرت رسالة «VCRUNTIME140.dll غير موجود» ثبّت Visual C++ Redistributable x64.
3. اضبط المقياس حسب الشاشة: افتح `start-display.bat` بالمفكرة وعدّل السطر `set SCALE=1.25`
   (1 لشاشة 1080p صغيرة، 1.25–1.5 لتلفاز 1080p كبير، 2 لشاشة 4K).

### ب) منظومة التغذية

1. ثبّت **Python** من python.org — **مهم:** فعّل خيار ☑ *Add python.exe to PATH* في أول شاشة التثبيت.
2. شغّل `install-feeder.bat` (مرة واحدة) — يثبّت pdfplumber و openpyxl.
3. أنشئ مجلد التقارير `C:\LSM\reports` وشاركه على الشبكة (زر أيمن ← Properties ← Sharing) مع صلاحية **كتابة** لموظف التقارير فقط.
   - إن كان المجلد في مكان آخر عدّل السطر `set REPORTS=C:\LSM\reports` في `start-feeder.bat`.
4. للتجربة: اسحب ملف تقرير وأفلته فوق `convert-report.bat` — يجب أن تظهر رسالة
   `✔ … المطابقة مع إجماليات التقرير دون فروق`، وتتحدث الشاشة خلال 5 ثوانٍ.

### ج) التشغيل التلقائي عند إقلاع الجهاز

1. اضغط `Win + R` واكتب `shell:startup` ثم Enter.
2. انسخ إليه **اختصارين** (Shortcut — لا الملف نفسه): لـ `start-display.bat` ولـ `start-feeder.bat`.
3. اضبط ويندوز لجهاز عرض دائم:
   - **Settings ← System ← Power:** Screen = Never، Sleep = Never.
   - **Windows Update ← Advanced ← Active hours:** من 8:00 إلى 16:00 (لمنع إعادة التشغيل أثناء الجلسة).
   - تسجيل دخول تلقائي لحساب مخصص للشاشة (حساب محلي بلا صلاحيات إدارية).
   - إيقاف الإشعارات وشاشة التوقف.
4. أعد تشغيل الجهاز وتحقق أن الشاشة والتغذية تبدآن وحدهما.

## 6. الإجراء اليومي

| الوقت | من | الإجراء |
|---|---|---|
| قبل الجلسة | لا أحد | الشاشة تعمل وحدها وتعرض «السوق مغلق» مع أرقام الجلسة السابقة ونصّ «الأرقام لجلسة سابقة» |
| أثناء الجلسة (اختياري) | موظف التقارير | كلما حدّث التقرير يحفظه في مجلد التقارير ← تتحدث الشاشة ويُضاف نقطة لمنحنى المؤشر |
| بعد الإقفال | موظف التقارير | يحفظ **التقرير النهائي** (Excel يُفضَّل على PDF) في مجلد التقارير — هذا هو الإجراء الوحيد المطلوب يوميًا |
| بعد الحفظ بدقيقة | موظف التقارير | ينظر إلى نافذة التغذية: «دون فروق» ✔، أو يقرأ التحذيرات ويراجعها |

**لا داعي لإعادة تسمية الملف** — التغذية تأخذ أحدث ملف في المجلد، وتقرأ تاريخ الجلسة من داخل التقرير.

## 7. ما يحدث آليًا وما ينبّه إليه النظام

| الحالة | ماذا يحدث |
|---|---|
| تقرير سليم | «المطابقة مع إجماليات التقرير دون فروق» والشاشة تتحدث |
| فرق بين مجموع الشركات وإجمالي التقرير | تحذير «مطابقة: …» في نافذة التغذية — يُراجع التقرير |
| شركة جديدة مدرجة غير معرّفة | تظهر برمز مؤقت + تحذير ← تُضاف إلى `data\companies.json` (البند 8) |
| تغيّر عدد أسهم شركة (زيادة رأس مال) | تحذير، ويُعتمد رقم التقرير تلقائيًا |
| ملف تالف أو نصف محفوظ | تبقى آخر بيانات سليمة على الشاشة، ويُعاد المحاولة تلقائيًا |
| توقفت التغذية أثناء الجلسة | مؤشر الحالة يتحول برتقاليًا «الجلسة جارية — بانتظار التحديث» بعد 10 دقائق |
| أُغلق برنامج الشاشة أو التغذية | يُعاد تشغيله آليًا خلال ثوانٍ (ملفات .bat) |

تحذيرات فحص البيانات تظهر للمشغّل فقط، **ولا تظهر للجمهور في وضع ملء الشاشة**.

## 8. الصيانة

### إضافة شركة جديدة مدرجة
افتح `data\companies.json` بالمفكرة (أو VS Code) وأضف سطرًا بنفس الصيغة:

```json
{ "sym": "XYZ", "name": "اسم الشركة بالعربي كما في التقرير", "en": "English name as in report", "sector": "القطاع", "shares": null },
```

- `en` يجب أن يطابق الاسم الإنجليزي في عمود Company بالتقرير.
- `shares` يُترك `null` — يُحسب تلقائيًا من القيمة السوقية في أول تقرير.
- إن اختلف الاسم العربي في التقرير عن الرسمي أضف: `"aliases": ["الاسم كما في التقرير"]`.
- احفظ الملف بترميز **UTF-8**. الشاشة تلتقط التعديل وحدها.

### تعطيل الشاشة مؤقتًا / وضع الصيانة
- `Esc` للخروج من ملء الشاشة، `F11` للعودة، `R` أو `F5` لإعادة القراءة فورًا.
- لتثبيت حالة السوق (مثلًا عطلة رسمية): عدّل `"status": "closed"` في `data\session.json`.

### تحديث البرنامج
نزّل الحزمة الأحدث من GitHub Actions، وانسخها فوق المجلد القديم **مع الإبقاء على مجلد `data`**.

### النسخ الاحتياطي
- مجلد التقارير (أرشيف رسمي) — يُنسخ دوريًا.
- `data\companies.json` — بعد كل تعديل.

## 9. استكشاف الأعطال

| العَرَض | السبب المحتمل | الحل |
|---|---|---|
| الشاشة لا تتحدث بعد حفظ التقرير | نافذة التغذية مغلقة أو المسار خطأ | تأكد أن `start-feeder.bat` يعمل وأن `REPORTS` يشير للمجلد الصحيح |
| «'python' is not recognized» | Python غير مضاف إلى PATH | أعد تثبيت Python مع تفعيل *Add to PATH* |
| «لقراءة ملفات PDF ثبّت المكتبة» | لم يُشغَّل install-feeder.bat | شغّله |
| «لم أجد جدول الأسهم في التقرير» | تغيّر شكل التقرير أو ملف ليس تقريرًا | أرسل نسخة من التقرير للمطوّر لإضافة أسماء الأعمدة الجديدة |
| الخط صغير/كبير على التلفاز | المقياس | عدّل `SCALE` في start-display.bat |
| الأحرف العربية مربعات | خط غير متوفر (نادر على ويندوز) | ثبّت خط Tahoma أو Noto Sans Arabic |
| الشاشة سوداء بعد التشغيل | مكتبات Qt ناقصة | لا تنقل ملف exe وحده — انقل المجلد كاملًا |

## 10. الأمن والحوكمة

- النظام **للقراءة فقط**: لا يتصل بنظام التداول ولا يرسل بيانات لأي جهة.
- صلاحية الكتابة في مجلد التقارير لموظف التقارير فقط؛ وحساب جهاز العرض بلا صلاحيات إدارية.
- كل تقرير يُحوَّل يُذكر اسمه في سطر «المصدر» أسفل الشاشة، ويُحفظ وقت التحديث — للتتبع والمساءلة.
- الشيفرة مفتوحة في المستودع، وكل تعديل يمر باختبارات آلية (منها اختبار على التقرير الرسمي) قبل إنتاج الحزمة.

## 11. التغذية المباشرة من قاعدة البيانات (تشغيل دون أي تدخل)

بدل انتظار حفظ التقرير، تقرأ الوحدة `tools/lsm_db_feeder.py` الأسعار مباشرة من قاعدة بيانات نظام التداول كل 15 ثانية أثناء الجلسة.

### ما يحدث آليًا
| الوقت | ما تفعله الوحدة |
|---|---|
| قبل الافتتاح بـ 15 دقيقة | تبدأ القراءة |
| أثناء الجلسة | قراءة كل 15 ثانية؛ كتابة الملف عند أي تغيّر، ونبضة كل 60 ثانية حتى لو لم تتغير الأرقام |
| بعد الإقفال بـ 30 دقيقة | لقطة ختامية، أرشفة `data/archive/session-YYYY-MM-DD.json`، ثم سكون حتى الجلسة التالية |
| الجمعة والسبت والعطل الرسمية | لا قراءة؛ والشاشة مثبتة على «السوق مغلق» في العطل (`data/holidays.json`) |
| انقطاع القاعدة | تبقى آخر أرقام سليمة، إعادة اتصال آلية، وتنبيه بالبريد بعد 5 دقائق، ثم رسالة عند العودة |
| فروق في المطابقة | تنبيه بالبريد مرة يوميًا |

### المطلوب من مسؤول قاعدة البيانات (مرة واحدة)
1. إنشاء جدولي العرض `LSM_DISPLAY_V` و `LSM_INDEX_V` من القالب `docs/db/sqlserver.sql` أو `docs/db/oracle.sql` بعد استبدال أسماء الجداول الأصلية.
2. إنشاء حساب **للقراءة فقط** على جدولي العرض فقط (في القالب نفسه).
3. فتح منفذ القاعدة (1433 لـ SQL Server أو 1521 لـ Oracle) **من جهاز الشاشة فقط**.

### المطلوب على جهاز الشاشة
1. تثبيت مشغّل القاعدة: `pip install pyodbc` (SQL Server، مع Microsoft ODBC Driver 18) أو `pip install oracledb` (Oracle).
2. تعبئة `tools/db_feeder.ini`: نوع القاعدة، العنوان، اسم المستخدم، ومواعيد الجلسة.
3. حفظ كلمة المرور في متغير بيئة: `setx LSM_DB_PASSWORD "..." /M` (لا تُكتب في الملف).
4. الاختبار: `test-db-feeder.bat` — يعرض الأعمدة ومطابقتها والنتيجة دون كتابة.
5. التشغيل الدائم: `install-db-feeder-task.bat` (كمسؤول) — مهمة تبدأ مع إقلاع الجهاز قبل تسجيل الدخول.
6. إيقاف `start-feeder.bat` (تغذية التقارير) من بدء التشغيل، أو إبقاؤه احتياطيًا لمجلد مختلف.

### التجربة قبل توفر القاعدة الحقيقية
```bash
python tools/lsm_db_feeder.py --make-demo-db tools/demo.sqlite
python tools/lsm_db_feeder.py --config tools/db_feeder.ini --test
```

### الضوابط الأمنية
- تُرفض أي تعليمة غير `SELECT` قبل إرسالها، وتُفتح الجلسة بوضع القراءة فقط حيث يدعمه المشغّل.
- الحساب لا يرى إلا جدولي العرض؛ ولا تُقرأ أي بيانات مستثمرين أو أوامر.
- ملف الحالة `data/feeder_status.json` وسجل `data/logs/db_feeder.log` للمراجعة والتدقيق.
